# 세로 합본 마감과 업로드 분할 규격

사용자가 선택한 컷들을 세로 스크롤 원고로 조립해 마감하고, 디시인사이드 등 커뮤니티 게시판에 깨짐이나 강제 축소 없이 전달하기 위한 기준을 정리한 문서다.

## 1. 컷 사이 실제 거리와 세로 조립

후보 컷을 골라 분리한 뒤 세로로 이어 붙일 때는 각 컷의 표시 배율, 좌우 정렬, 컷 사이 간격을 함께 조정한다([컷 기반 제작](CUT_BASED_PRODUCTION.md), [호흡과 간격](PANELING_AND_PACING.md) 참고).

- **컷 사이 실제 거리 = 앞 컷 아래 흰 여백 + 추가 간격 + 다음 컷 위 흰 여백**
- 잘라낸 각 컷 이미지의 위아래에 이미 흰 여백이 남아 있다면, 목표 거리에서 **부족한 만큼만 추가 간격으로 더한다**. 기존 여백을 빼지 않고 거터 수치를 그대로 더하면 컷 사이가 지나치게 벌어진다.
- 빠른 응답, 짧은 반응, 정보 공개, 침묵, 진짜 장면 전환을 구별해 간격을 차등 적용한다.

## 2. 모바일 최종 표시 폭과 실제 기기 가독성

- 커뮤니티 독자 다수는 스마트폰 화면이나 폭이 좁은 게시글 본문 영역에서 만화를 읽는다. 따라서 생성 입력 단계부터 글자 크기·명암 대비·말풍선 안 여백의 목적을 전달하고, 세로 편집 단계에서도 최종 표시 폭으로 줄였을 때 글자가 뭉개지지 않는지 확인한다.
- 사용자가 기존 생성 이미지의 글자를 그대로 유지하기로 결정한 컷은 후처리에서 임의로 덮어쓰지 않고 보존한다.
- **데스크톱 축소 확인과 실제 기기 확인은 다르다**: 데스크톱 모니터에서 창 크기를 줄여 보는 것과 실제 스마트폰 화면에서 손가락으로 스크롤하며 읽는 체감 속도와 가독성은 다르므로 두 확인을 구별한다.

## 3. 디시인사이드 업로드 기준과 2026-10-21 관측 배경

디시인사이드 게시용 분할본을 만들 때 적용하는 **파일당 20,000,000바이트(20MB) 미만, 세로 9,000px 이하** 기준은 2026-10-21 실제 게시글 본문에서 긴 이미지가 자동 축소된 현상을 관측한 뒤 사용자가 채택한 **안전 제작 기준**이다.

> **주의**: 이 수치는 실제 관측 뒤 채택한 작업 기준이며, 디시인사이드의 공식 발표 한도라거나 모든 갤러리·모든 게시글의 서버 동작이라고 단정해 적지 않는다.

### 실제 관측과 적용 사례
- **〈꾸준툰 새로쓰기〉 (2026-10-17 완성, 최종 승인 65컷)**:
  - 실제 게시글(`https://gall.dcinside.com/mgallery/board/view/?id=thesingularity&no=1493087&page=1`)에서 원본보기 기준 `1024x18255px`였던 세로 이미지가 게시글 본문에서 `560x9999px`로 줄어들어 표시되는 현상이 확인되었다.
  - 이에 따라 2026-10-21 파일당 20,000,000바이트 미만·세로 9,000px 이하 기준을 세우고, 원본 폭과 화질을 지키는 **13구간 조정본**으로 다시 분할했다(기록상 새 13구간본의 재업로드는 미실행 상태다).
- **미소녀툰 〈왜 특갤러들은 미소녀가 되고 싶어 하는가〉 (2026-10-21 완성, 선택 21컷)**:
  - 같은 기준(파일당 20,000,000바이트 미만·세로 9,000px 이하)을 적용해 **최종 4구간**으로 분할 완성했다(게시 URL은 아직 없다).
- 꾸준툰은 [2026-10-23 실시간 베스트 게시글](https://m.dcinside.com/board/dcbest/472493)로 연결된다. 현재 원글과 실베의 첨부는 6개이며, 13구간 조정본이 게시됐다는 뜻은 아니다.

## 4. 안전한 흰 여백에서의 무손실 분할과 보관

1. **전체 보기본(마스터 합본) 별도 보관**: 분할하기 전, 작품 전체가 한 흐름으로 이어진 전체 보기본은 별도로 보관한다.
2. **안전한 흰 여백에서만 분할**: 세로 길이나 용량을 나눌 때는 절대 그림이나 말풍선, 글자를 가로질러 자르지 않고 **컷 사이의 안전한 흰 여백(거터) 행**에서만 나눈다.
3. **원본 픽셀·행·글자·여백 무손실 보존**: 분할 과정에서 가로 폭을 리사이즈하거나 손실 재압축해 글자와 선을 흐리지 않는다. 분할된 구간들을 세로로 다시 이어 붙였을 때 **원본 가로 폭, 픽셀 값, 전체 행(row) 수, 글자, 기존 여백**이 그대로 보존되어야 한다.
4. **번호순 전달**: 업로드할 때 순서가 뒤바뀌지 않도록 파일 이름을 번호순(`01`, `02`, ...)으로 정리해 전달한다.

## 5. 공개 키트 `freeze_completion.py`의 범위와 별도 도구 준비

- 공개 저장소(`Q0916/community-webtoon-agent-kit`)에 포함된 `freeze_completion.py`는 최종 채택된 파일들을 마감 경로로 복사하고 SHA-256 해시를 기록·검증하는 도구다.
- `freeze_completion.py`와 공개 키트 자체에는 **세로 9,000px 이하·20,000,000바이트 미만 여부를 검사하거나, 흰 여백을 찾아 무손실로 분할하고 재결합 일치 여부를 자동 검사하는 기능이 포함되어 있지 않다**.
- 따라서 세로 편집, 무손실 여백 분할, 높이·용량·재결합 검사는 사용자가 별도의 이미지 편집/검사 도구를 준비해 수행해야 하며, 공개 키트에 없는 CLI 명령이나 옵션을 있는 것처럼 적지 않는다.
