# Quality Contract

이 키트가 재현하려는 것은 특정 그림체가 아니라, 결과를 안정시키는 제작 의사결정 구조다.

## 0. 이해 일치가 미시 프롬프트보다 먼저다

정확하고 철저한 수행 지시만으로는 창작 품질을 재현할 수 없다. 작품 전체 이야기, 독자가 느껴야 할 감정 순서, 장면의 존재 이유, 정확한 모티브, fact/MSG 경계, 사용자가 감지한 미묘한 어긋남처럼 당장의 명령에는 쓰잘데기 없어 보이는 문맥이 실제 장면 선택과 연기를 바꾼다.

이 원칙은 작업 철학이 아니라 시행착오에서 확인된 품질 상승 방법이다. 분업할 때마다 다음 판단에 필요한 판단을 복원할 수 있는 충분한 맥락를 다시 전달한다. 경로·해시·레퍼런스·이전 출력은 provenance와 화면 상태를 증명하지만 작품 의미를 자동으로 전달하지 않는다.

프롬프트를 줄일 때는 중복된 수행 지시를 먼저 줄인다. 작품 전체 이유와 감정선은 `soft context`라는 이유로 제거하지 않는다.

## 1. 소스 진실과 개그 MSG를 분리한다

원장은 최소 네 종류를 가진다.

- `primary_fact`: 실제 사건과 주장.
- `mood_source`: 커뮤니티의 반응, 말투, 밈 자세.
- `MSG`: 재미를 위해 창작하거나 과장한 연결과 대사.
- `do_not_use`: 오래됐거나 반박됐거나 현재 주제와 무관한 자료.

커뮤니티에서 실제로 관측되지 않은 분위기를 대표 여론처럼 쓰지 않는다. 창작 대사는 가능하지만 MSG로 표시한다.

## 2. 스윗스팟을 승인받는다

콘티 전에 세 축을 한 문장으로 겹친다.

1. Director가 보여주고 싶은 주장과 감정.
2. 해당 커뮤니티 독자가 기대하는 말맛과 장면.
3. 상업적으로 보여줘야 할 것: 그림·연기·선·구도·여백과 독자가 채우는 생략이 주는 직관적 정보와 시각적 보상.

이 합의가 없으면 자료 요약은 가능해도 만화의 방향은 잠그지 않는다.

## 3. 정보 배열을 인과 콘티로 바꾼다

각 컷은 다음 네 질문에 답한다.

- `handoff_from_previous`: 왜 지금 이 컷으로 넘어오는가?
- `reader_first_sees`: 독자가 가장 먼저 보는 것은 무엇인가?
- `character_realizes`: 인물은 방금 무엇을 알거나 오해하는가?
- `push_to_next`: 그래서 왜 다음 행동이나 반응이 생기는가?

끝맺음은 작품이 원하는 경험에 맞춘다. 앞의 질문이나 농담을 회수할 수도 있고, 열린 가능성과 다음 일상의 여운을 남길 수도 있다. 그 기능과 이유를 다음 작성자에게 전달한다.

## 3A. 거친 뼈대의 빈칸을 Gemini가 채우고, 사람이 함께 정리한다

자료 해석, 장면 선택, 말맛, 타이밍, 펀치라인은 프론트 창작 작업이다. GPT/Codex는 구조 누락과 소스 불일치를 점검할 수 있지만, 자신이 쓴 콘티의 창작 품질을 스스로 보증할 수 없다.

필수 경로:

1. Director/Producer의 거친 장면 뼈대를 별도 파일로 보존한다. 의도적으로 맡길 빈칸을 먼저 완성하지 않는다.
2. Gemini가 전체 소스 근거와 fact/MSG 경계를 읽고 그 빈칸, 말맛, 연출, 타이밍을 채운다. 원출력을 그대로 보존한다.
3. 사람이 두 원본을 함께 보며 제안을 `adopt`, `adapt`, `reject`로 정리한다. Codex의 사실·연속성 정정이 작품 안에 등장해도 된다.
4. 합의된 결과만 하나의 canonical 콘티로 통합하고 사람이 최종 승인한다.
5. 사람 승인 canonical 버전만 이미지용 패킷과 프롬프트의 기준선으로 쓴다.
6. 각 단계의 파일과 버전을 `editorial_review_lock.csv`에 기록한다.

Gemini 원출력 보존, 공동 adopt/adapt/reject 검토, 사람 승인이 빠지면 구조 검사가 통과해도 이 키트의 품질 보장 범위 밖이다.

## 4. 텍스트 내용과 배치를 따로 잠근다

Source lock은 “무슨 글자를 써도 되는가”를 증명한다. Routing lock은 “그 글자가 누구에게 어디로 붙는가”를 증명한다. 둘 중 하나만 있으면 말풍선 꼬리, 소품 글자, 댓글 카드, 화자 귀속이 흔들린다.

후보 생성에서는 기능적 위치를 지시하고 좌표는 강제하지 않는다. 긴 정확 문장은 생성 모델보다 후속 식자를 우선한다.

## 5. 캐스트와 레퍼런스를 데이터로 다룬다

화면에 보이는 인물마다 역할 ID를 둔다. 반복 캐릭터는 파일 경로, 역할, SHA-256, 사람의 visual-role 확인 상태를 기록한다. 다른 역할이 같은 해시를 가리키면 생성 전에 멈춘다.

연속 장면은 캐릭터 시트와 별도로 직전 승인 후보를 scene-continuity reference로 붙인다.

장면 관계는 이미지 생성 전에 `independent_page`, `same_scene_continuation`, `reused_shot_variation` 중 하나로 선언한다. 이야기와 대사가 다음 페이지로 이어진다는 사실은 visual continuity의 증거가 아니다. 스킬/프로듀서가 관계를 판단하고, 하네스는 선언된 값과 prompt의 scene reference 일치만 검사하며, provider runtime은 이를 재해석하지 않는다.

## 6. 화면을 positive inventory로 설계한다

현재 검증된 기본 이미지 생성 실행기는 `ima2-gen`이다. 스킬이 이야기와 장면 의미를 판단하고, 하네스가 승인·잠금·입력 일치를 검사하며, ima2-gen은 실제 생성 요청을 실행한다. `generation_plan.csv`에는 실제 사용한 runtime 이름을 기록한다.

provider prompt는 다음을 명시한다.

- 정확한 visible cast
- 보일 수 있는 오브젝트와 정보 소품
- 렌더할 텍스트 행과 소유자
- background budget
- 그림 블록의 경계
- 자세, 실루엣, 색, 카메라, 읽기 순서

불필요한 요소를 장문의 금지 목록으로 provider에게 가르치지 않는다. 반려 사유와 오염 위험은 audit 쪽에 둔다.

## 7. 흰 원고지 문법을 페이지 계약으로 만든다

흰 세로 원고를 출발점으로 삼고 `PANEL_LAYOUT_REVISION.md`에 따라 컷의 점유·크기·위치·식자·여백·경계를 퇴고한다. 초기 2~4블록·28~42% 여백은 배치 예로 보존하며, 실제 페이지는 원하는 독자 경험에 맞춰 정한다. 스플래시·작은 반응·반복 배치도 장면의 이유로 선택할 수 있다.

## 8. 작은 파일럿과 사람 검수를 분리한다

처음부터 전체 배치를 만들지 않는다. 한 페이지 또는 작은 배치로 provider가 한국어, 레퍼런스, 캔버스 계약을 실제로 보존하는지 확인한다. 기술적으로 성공해도 창작 품질은 Director가 직접 본다.

## 9. 상태 표면을 깨끗하게 유지한다

현재 후보, 선택본, 반려본, 레거시를 분리한다. 구버전이 current나 prompt queue에 남아 다음 생성의 참고물이 되는 것이 반복 오염의 큰 원인이다.

## 10. 최종 승인은 보관 꼬리까지 포함한다

완성은 다음 세 묶음을 해시로 동결할 때 끝난다.

- 게시·열람용 완성본
- 사용자가 최종 승인한 개별 원본
- 실제 사용한 소스, 레퍼런스, 콘티, 프롬프트, 선택 기록

나머지 작업 이력은 legacy로 분리하되 자동 삭제하지 않는다.
