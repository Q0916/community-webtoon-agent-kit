# 처음부터 끝까지 읽고 단계별로 진행하기

에이전트가 이미 정리된 제작 원칙과 작법 요령을 빠뜨리지 않고 제때 적용하도록 돕는 진행 가이드입니다. 기존 집필·검증·생성·사람 선택·완성 보관 계약을 유지하면서, 최신 **1-2컷 시트 생성 → 세로 편집 → 무손실 분할** 흐름까지 한눈에 이어줍니다.

## 최신 기본 제작 흐름

현재 실제 작품 제작은 다음 순서로 이어집니다.

1. **작품과 의도 이해**: 원문 소재와 댓글 분위기, 창작 MSG, 작품이 노리는 재미와 독자 경험을 합의합니다.
2. **전편의 감정·인과·보상 퇴고 → 장면 연결 → 컷 설계**: 처음부터 컷 단위로 쪼개지 않고, 전편 전체의 감정선과 인과·보상을 먼저 세운 뒤 장면 연결을 다듬고 마지막에 컷을 설계합니다([작법 퇴고](CRAFT_REVIEW.md)). 무엇을 왜 유지·수정했는지는 기존 콘티 메모에 남기며, 매 컷 새 보고서나 별도 승인 절차를 추가하지 않습니다.
3. **전체 흐름·현재 구간·앞뒤 상태·정확한 대사·WHY를 담은 실제 입력 조립**: 장면 이해에 필요한 발화자·상대·반응·핵심 볼거리를 보존하고 불필요한 구경꾼·반복 배경·연속성 부담을 줄입니다. 작화 묘사에는 실제 화면에 보일 면과 글자만 적되, 소품의 이야기상 이유와 폰 표시 폭 기준의 가독성 목적(글자·대비·말풍선 공간)은 본문 맥락으로 전달합니다.
4. **분리 가능한 1-2컷 시트 후보 생성과 사용자 선택**: 승인된 장수·비용 안에서 단위 시간당 사람이 고를 만한 후보 수를 확보하고, 사용자가 직접 선택합니다([컷 기반 제작](CUT_BASED_PRODUCTION.md)).
5. **컷별 크기·정렬·간격을 정한 세로 편집**: 생성 시트 안의 배치와 최종 스크롤 배치는 다른 단계입니다. 분리한 컷의 기존 위아래 흰 여백을 먼저 재고(`앞 컷 아래 흰 여백 + 추가 간격 + 다음 컷 위 흰 여백`), 응답·반응·공개·침묵·진짜 장면 전환에 맞춰 목표 거리의 부족분만 더합니다([호흡·간격](PANELING_AND_PACING.md)).
6. **승인본·전체본 보관 및 게시용 무손실 분할**: 전체 보기본을 별도로 보관하고, 커뮤니티 업로드용 파일은 안전한 흰 여백에서 원본 폭·픽셀·행·글자·기존 여백을 그대로 보존해 무손실 분할한 뒤 번호순으로 전달합니다([업로드와 무손실 분할](UPLOAD_DELIVERY.md)).

## 시작과 단계 전환

1. 시작할 때 이 문서와 [기본 스킬](../skills/community-webtoon-producer/SKILL.md)의 `Required Workflow`를 처음부터 끝까지 읽고, 이번 작품 경로에 해당하는 단계별 매뉴얼을 끝까지 읽습니다.
2. 작품별 `PRODUCTION_CHECKLIST.md` 하나에 현재 단계, 읽을 매뉴얼과 예시, 실제 완료 조건을 적습니다. 프로젝트 초기화 스크립트(`init_project.py`)는 [시작 양식](../harness/templates/production_checklist.md)을 복사합니다.
3. 단계에 들어갈 때 체크리스트, 해당 단계 매뉴얼·예시, 직전 단계 결과물을 읽습니다.
4. 작업 후에는 실제 원고·입력·첨부·결과물에서 완료 조건이 반영되었는지 확인합니다. 완료된 항목에만 체크하고 결과 경로와 적용 근거, 남은 문제를 짧게 적습니다.
5. 단계가 끝나면 체크리스트를 갱신한 뒤 다음 단계 매뉴얼을 읽습니다. 작업이 중단되었다가 이어질 때도 현재 단계와 다음 읽을 문서부터 확인합니다.

**‘매뉴얼을 읽거나 자료를 첨부함’ 또는 ‘기술 검사 PASS’와 ‘실제 원고·결과에 퇴고를 적용함’은 서로 다릅니다.** 예를 들어 작법 퇴고는 실제 콘티에서 전편→장면→컷 인과와 핵심 볼거리가 살아났는지를 뜻하고, 세로 편집은 앞뒤 컷의 기존 흰 여백을 잰 실제 거리 계산과 모바일 표시 폭 가독성을 뜻합니다. 체크리스트는 제작자 내부 기록이며 매 단계마다 사용자 재승인이나 새 보고서를 요구하는 절차가 아닙니다.

공개 키트가 기본 제공하는 5개 스크립트(`init_project.py`, `validate_project.py`, `provider_instruction_integrity.py`, `freeze_completion.py`, `verify_repository.py`)의 지원 범위와 사용자가 별도로 준비할 편집·분할 환경을 분명히 구별합니다.

- 공개 `validate_project.py`는 기존 `page_id` 기반 잠금과 Gemini 원출력/사람 승인 기록을 검사하며, 새 1-2컷 시트 프로필을 자동 검증하지 않습니다.
- 공개 `freeze_completion.py`는 복사와 SHA-256 검증 도구이며, 업로드용 높이·용량 검사나 무손실 분할·재결합 검사는 별도 도구로 수행합니다.
- 기존 전체 페이지 프로필(60%/78% 표현 예산 등)과 새 1-2컷 시트 프로필은 합치지 않고 구별하며, 특정 작품의 해상도·컷 수·중앙 흰띠 폭·인물 수 상한·의상·배율·간격을 모든 작품의 규칙으로 복사하지 않습니다.

## 통과 결과는 재사용하기

입력·순서·참조·규칙과 증거가 유효한 완료 항목은 그대로 유지하고, 수정으로 영향을 받은 구간과 의존 항목만 다시 확인합니다. 전체 대본이 바뀌어 입력 전체가 달라진 경우에만 전체 범위를 다시 점검합니다. 매뉴얼을 다시 읽거나 체크리스트를 갱신한다는 이유로 이미 통과한 모든 기술 검사를 반복 실행하지 않습니다. 실제 기계적 재사용은 현재 실행기(`ima2-gen` 등)와 작업 환경이 제공하는 범위에서 수행하며, 공개 키트에 별도의 검사 캐시나 누적 receipt 저장소가 들어 있는 것은 아닙니다.

## AGY에는 짧은 자연어와 실제 자료

AGY/Gemini에게 집필이나 문장 편집·연출을 부탁할 때는 짧고 자연스럽게 말합니다. 거친 뼈대의 빈칸 채우기뿐 아니라 자유 집필, 완성된 원고의 퇴고와 문장 정리도 실제 위임에 따라 요청할 수 있습니다. 작품 원문, 사용자 의도, 필요한 매뉴얼과 예시를 함께 주되, 내부 체크리스트를 긴 작업지시서나 고정 출력 틀로 넘기지 않고 모델이 제안할 여지를 남깁니다. 사용자가 구체적인 출력 형식을 지정한 경우에는 그 요청을 따릅니다.

> 안녕? 웹툰 연출 좀 도와줄래? 여기 내가 리서치로 만든 매뉴얼과 예시가 있어. 만화 내용을 읽고 어떻게 나눠붙이는 게 좋을지 알려줘!

짧은 부탁과 충분한 맥락 자료는 함께 갈 수 있습니다. 파일 경로만 적는다고 읽기 권한이 생기지 않으므로, 직접 읽을 수 없는 환경이라면 필요한 전문을 본문에 넣어 전달하고 이미지는 실제 첨부나 허용된 읽기 경로로 준비합니다. 빈 응답을 자료 열람 완료로 처리하지 않으며, AGY 실제 원출력 보존과 사용자의 채택·실행 권한은 언제나 유지합니다.
