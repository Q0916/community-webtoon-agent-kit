# 처음부터 끝까지 읽고 단계별로 진행하기

에이전트가 이미 있는 제작 요령을 제때 적용하도록 사용하는 내부 진행 방식입니다. 기존 집필·검증·생성·사람 선택·완성 보관 단계를 유지합니다.

## 시작과 단계 전환

1. 시작할 때 이 문서와 기본 스킬의 `Required Workflow`를 처음부터 끝까지 읽고, 이번 작품에 사용하는 단계별 매뉴얼도 끝까지 읽습니다. 아래 읽기 지도에서 실제 경로를 확인합니다.
2. 작품별 `PRODUCTION_CHECKLIST.md` 하나에 현재 단계·필요한 매뉴얼과 예시·완료 조건을 둡니다. 초기화 도구는 [시작 양식](../harness/templates/production_checklist.md)을 복사합니다. 기존 작품은 필요한 범위에서 같은 양식을 사용할 수 있습니다.
3. 단계 진입 시 체크리스트, 해당 단계 매뉴얼·예시, 직전 결과를 읽습니다.
4. 작업 후 실제 입력·첨부·결과에서 완료 조건을 확인합니다. 완료 항목에만 체크하고 결과물과 적용 근거, 남은 문제를 짧게 기록합니다.
5. 단계 종료 시 체크리스트를 갱신한 뒤 다음 단계 매뉴얼·예시를 읽습니다. 중단 후에는 현재 단계와 다음 읽을 문서에서 이어갑니다.

'매뉴얼을 읽음'과 '실제 결과에 적용함'은 구별합니다. 예를 들어 컷 배분은 실제 제출문의 컷 수를, 간격은 대화·반전·침묵 연결의 실제 배치를 확인합니다. 체크리스트는 제작자 내부 기록이며 매 단계 사용자 재승인이나 별도 검토 보고서를 추가하는 절차가 아닙니다. 기존 사용자 판단과 실행 권한은 유지합니다.

## 읽기 지도와 완료 증거

| 단계 | 읽을 자료 | 실제 완료 대상 |
|---|---|---|
| 0 전체 흐름 | 이 문서, [기본 스킬](../skills/community-webtoon-producer/SKILL.md), 아래에서 사용하는 매뉴얼 | 이번 작품의 체크리스트와 실행 경로 |
| 1 소재·의도 | [시작 전 준비](BEFORE_YOU_START.md), [품질 계약](QUALITY_CONTRACT.md), 작품 원문·사용자 대화 | 작품의 목적·독자 경험·현재 합의와 근거 |
| 2 콘티·퇴고 | [역할](CREATIVE_ROLES.md), [창작 맥락](CREATIVE_CONTINUITY.md), [배치 퇴고](PANEL_LAYOUT_REVISION.md), 해당 작법·캐릭터 자료 | 실제 이야기·장면·컷의 선택, 원출력과 채택 콘티·화자·순서 |
| 3 입력 조립 | [실행 연결](PROVIDER_ADAPTER.md), [원문 전달](../harness/templates/panel_prompt.txt), 품질 계약 | 전체 맥락·현재 페이지·정확한 식자·시트 배분·참조가 결합된 실제 입력 |
| 4 생성 | 실행 연결과 현재 제공자 매뉴얼·승인 범위 | 실제 요청·성공 원본·실패·출처; 기술 성공과 시각 선택 구별 |
| 5 선택 | 품질 계약과 현재 전달·선택 기록 | 실제 남긴 원본·순서·누락과 사용자 판단 |
| 6 세로 편집 | 배치 퇴고, [호흡·간격](PANELING_AND_PACING.md) 전문과 작품 예시 | 표시 크기·위치·연결별 거리·기존 여백을 반영한 실제 읽기본 |
| 7 완성 보관 | 품질 계약의 완료 경계, [완성 보관 도구](../harness/scripts/freeze_completion.py) | 채택 완성본·선택 원본·사용 자료·무결성과 완료 상태 |

현재 도구가 지원하는 전체 페이지·컷 시트·후편집 범위를 실제 매뉴얼에서 확인합니다. 프로젝트에 없는 도구를 있다고 가정하거나 다른 제작 환경의 실행기를 자동으로 요구하지 않습니다. 간격 수치는 기존 제작의 참고 처방이며 장면 기능·표시 폭·실제 여백을 함께 보고 사용합니다.

## 통과 결과는 재사용하기

입력·순서·참조·규칙과 증거가 유효한 완료 항목은 유지합니다. 수정으로 영향을 받은 항목과 의존 구간만 다시 확인합니다. 전체 대본이 바뀌어 전체 입력이 달라지면 해당 범위를 다시 확인합니다. 매뉴얼 재독과 체크리스트 갱신 때문에 모든 기술 검사를 다시 실행하지 않습니다. 실제 기계적 재사용은 현재 실행기가 제공하는 캐시·receipt 범위에 따릅니다. 이 문서는 공개 키트에 없는 검사 캐시를 새로 제공한다고 주장하지 않습니다.

## AGY에는 짧은 자연어와 실제 자료

AGY/Gemini에 창작을 부탁할 때는 짧고 자연스럽게 말합니다. 작품·사용자 의도 원문·필요한 매뉴얼과 예시를 함께 주고, 모델이 상상하고 제안할 여지를 넓게 남깁니다. 내부 체크리스트를 긴 작업지시서나 고정 출력 틀로 전달하지 않습니다. 사용자가 구체적인 출력 형식을 요청하면 그 요청을 따릅니다.

> 안녕? 웹툰 연출 좀 도와줄래? 여기 내가 리서치로 만든 매뉴얼과 예시가 있어. 만화 내용을 읽고 어떻게 나눠붙이는 게 좋을지 알려줘!

짧은 부탁과 충분한 자료는 함께 사용할 수 있습니다. 파일 경로만으로 읽기 권한이 생기지 않습니다. 문서를 읽을 수 없다면 필요한 전문을 본문으로 주고, 이미지는 실제 첨부 또는 허용된 읽기 경로를 준비합니다. 빈 응답을 자료 열람 완료로 체크하지 않습니다. 원출력 보존과 사용자의 채택·실행 권한은 유지합니다.

문서 반영과 효과 확인은 구별합니다. 다음 실제 작품에서 누락과 불필요한 재검사가 줄었는지 확인합니다. 기존 작품을 다시 생성하거나 기존 검증기를 교체하는 변경은 아닙니다.
