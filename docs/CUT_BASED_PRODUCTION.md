# 컷 기반 제작과 세로 스크롤 편집

특갤툰 등 커뮤니티 웹툰을 만들 때 현재 실제로 사용하는 기본 제작 흐름을 정리한 문서다. 한 번에 긴 페이지 전체를 완벽히 뽑아내려 하기보다, **이야기 퇴고 → 컷 설계 → 맥락을 담은 생성 입력 → 분리 가능한 1-2컷 시트 후보 생성 → 사용자 선택 → 컷별 세로 편집 → 승인본 보관 및 업로드 분할**의 순서로 진행한다.

## 1. 최신 기본 제작 흐름

1. **작품과 의도 이해**: 사용자가 무엇을 보고 이 만화를 시작했는지, 어떤 독자에게 어떤 웃음·공감·여운을 주려는지 합의한다([창작 연속성](CREATIVE_CONTINUITY.md), [역할과 판단](CREATIVE_ROLES.md) 참고).
2. **전편 → 장면 → 컷 순서의 퇴고**: 처음부터 컷 테두리를 쪼개지 않고, 전편의 감정선과 인과·보상(payoff)을 먼저 다듬은 뒤 장면 연결과 개별 컷을 설계한다([작법 퇴고](CRAFT_REVIEW.md) 참고).
3. **맥락과 이유(WHY)를 담은 실제 생성 입력**: 각 생성 요청 본문에는 전체 이야기 흐름, 현재 구간의 역할, 앞뒤 컷의 상태, 정확한 한국어 대사, 그리고 왜 이 표정·소품·구도가 필요한지(WHY)를 직접 담는다. 모바일 축소 환경에서도 글자가 잘 읽히도록 글자 크기·대비·말풍선 공간의 목적도 함께 전달한다.
4. **분리 가능한 1-2컷 시트 후보 생성**: 나중에 컷 단위로 깨끗하게 잘라낼 수 있는 1-2컷 시트 형태로 후보를 생성한다.
5. **사용자 선택**: 성공적으로 회수된 후보들 가운데 사용자가 연기·구도·말맛이 살아 있는 컷을 직접 고른다.
6. **컷별 크기·정렬·간격을 정한 세로 편집**: 선택된 컷들을 분리한 뒤, 각 컷의 표시 배율, 좌우 위치, 컷 사이 실제 거리를 조정해 세로 스크롤 읽기 경험을 완성한다([호흡과 간격](PANELING_AND_PACING.md) 참고).
7. **승인본 보관 및 업로드용 무손실 분할**: 끊김 없는 전체 보기본을 보관하고, 게시처 기준에 맞춰 안전한 흰 여백에서 무손실 분할해 번호순으로 전달한다([업로드와 전달 규격](UPLOAD_DELIVERY.md) 참고).

## 2. 생성 시트 내부 배치와 최종 스크롤 배치는 다른 단계다

생성 단계에서 1-2컷 시트를 쓰는 이유는 모델이 한 호흡의 연기와 구도에 집중하게 하고, 컷과 컷 사이에 분리용 안전 여백을 확보하기 위해서다. 반면 독자가 스마트폰이나 PC에서 스크롤하며 느끼는 속도감과 침묵은 **선택 후 세로 편집 단계**에서 각 컷의 표시 크기, 좌우 정렬, 컷 사이 간격을 어떻게 조립하느냐에 따라 결정된다.

따라서 **생성 시트 안의 내부 배치와 최종 스크롤 배치를 같은 단계로 혼동하지 않는다**.
- 특정 작품에서 사용했던 `1024x1536` 해상도, 총 컷 수, 시트 중앙의 고정 흰띠 폭, 인물 수 상한, 특정 의상, 배율과 간격 수치를 모든 작품의 공용 규칙으로 복사하지 않는다.
- 이전 세대의 **전체 페이지 프로필**(큰 흰 원고 안 폭 약 60%·높이 약 78% 작화 영역과 할당 토큰 집중 가설을 쓰는 페이지 단위 제작) 및 그 채택 입력은 2026-09-12 수학자툰, Amazon × OpenAI 사례 등 해당 작품을 재현하는 범위로 보존하며, 새 컷 시트 프로필과 억지로 합치지 않고 구별한다([컷 배치 퇴고](PANEL_LAYOUT_REVISION.md) 참고).

## 3. 후보 생성 운영: 승인 범위 안의 유효 후보 수 우선

이미지 생성 단계의 목표는 사용자가 승인한 장수와 비용 한도 안에서 **단위 시간당 사람이 실제로 고를 만한 유효 후보 수**를 확보하는 것이다.

- **후보 풀·웨이브·동시 실행 수의 구별**: 전체 목표 후보 풀(candidate pool), 한 번에 내보내는 웨이브(wave), 순간 동시 실행 수(concurrency)를 구별해 운영한다. 개별 요청의 일시적 실패율만 보고 사용자 확인 없이 자동으로 소규모 모드로 축소하지 않는다.
- **사용자 제한 우선과 원본 회수**: 사용자가 정한 수량과 재시도 상한을 최우선으로 따른다. 요청마다 고유 식별자를 남겨 늦게 완료된 성공본(late success)까지 빠짐없이 회수하고, 성공 원본을 덮어쓰지 않고 보존한다. 최종 시각 후보 선택은 언제나 사용자가 한다.
- **파일럿(pilot)과 재시도 지침의 정확한 의미**: 기존 템플릿과 워크플로의 파일럿 배치는 새 프로젝트 첫 도입이나 입력 구조 변경이 실제 실행기에 제대로 전달되는지 확인하는 점검이지, 매번 작은 배치만 강제하는 족쇄가 아니다. 기존의 재시도 지침 역시 현재 사용자가 승인한 수량·비용 범위 안에서만 적용한다.

## 5. 공개 저장소 도구의 범위와 별도 준비 환경

공개 저장소(`Q0916/community-webtoon-agent-kit`)는 Python 3.10+ 표준 라이브러리만으로 실행되는 다음 다섯 가지 스크립트를 제공한다.
- `init_project.py`: 프로젝트 기본 디렉터리와 템플릿 초기화
- `validate_project.py`: 기존 `page_id` 기반 소스·방향·콘티·잠금·프롬프트 검사
- `provider_instruction_integrity.py`: 전달 지시문과 해시 무결성 확인
- `freeze_completion.py`: 채택된 완성 파일 복사와 SHA-256 검증
- `verify_repository.py`: 필수 파일·미디어 제외·개인 경로 및 토큰 패턴·스킬 메타데이터 검사

실제 이미지 생성 실행기인 `ima2-gen`은 별도로 설치해 사용하며, **공개 키트 자체에는 생성 runner, 누적 receipt 관리 도구, 컷 시트 자동 분리·재배치 도구, 업로드용 무손실 분할 도구가 포함되어 있지 않다**. 또한 공개 `validate_project.py`는 기존 페이지 ID 기반 잠금 형식을 검사하므로, 새 컷 시트 프로필이나 세로 재조립 결과를 자동으로 검증해 준다고 주장하지 않는다. 컷 시트 분리·세로 편집·무손실 분할 환경은 사용자가 자신의 작업 환경에 맞춰 별도로 준비한다.
